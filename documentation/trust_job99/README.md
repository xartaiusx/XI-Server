# Trust job99 catalogs

[Valaineral](valaineral.json) is a default-off source candidate. [Iroha II](iroha_ii.json) is inactive preparation. Neither catalog is native test, deployment, gameplay acceptance, or a complete verified retail Trust roster.

The catalogs project the independently reviewed source audit of base `02c7f2f7729161b1fd3e9588bc28f7c1c652b02a` (audit SHA256 `bb9f5f2bd284f81e883f849c971ef81fb8915c7d28572482d05e603f12c832c1`). `source_layers` separates native base, enrolled overrides, and this candidate. `source_files` pins the public source files; each entry retains its source line. SQL catalog rows and active definitions are distinguished from commented placeholders, actual learning, current weapon admission, and runtime use. Native loaders are recorded explicitly; merits use the loaded YAML dataset, while the action/trait/skill catalogs use their recorded SQL loaders.

Valaineral has 24 normal PLD spells, gift Enlight II (855), one preserved baseline Banish III (30) exception, 25 PLD/WAR JAs, 20 trait families, 19 trained skill families, and 102 job weapon-skill entries. Equipment-only entries remain separate. The full learned catalog includes actions for other weapons, while current Sword admission is narrower. Uriel remains a signature. Banish III's Trust provenance and the Enlight II 460-skill anomaly remain unresolved.

Iroha II has 112 ordinary WHM spells, 23 SAM/WHM JAs, 15 trait families, 15 trained skill families, and 56 job weapon-skill entries. Reraise IV (848) is defined with zero job bytes and needs its qualified gift adapter; Full Cure (893) is not actively defined. Flare II (205) is a signature exception, not a third BLM job. Active signature-named 373x records are unassigned, unqualified catalog rows without confirmed action implementations. The current native pool models Sword (3); the intended polearm identity requires a reviewed repair. Store TP, Overwhelm, Cure cast-time and other consumers remain visible preparation blockers. No Iroha activation setting is introduced; Valaineral's flag cannot activate its unapproved profile.

The approved extension gives both assigned jobs main-job 99 privilege and literal 99/99 fields. Use still requires the correct weapon, native MP/TP, selected legal merit unlocks, status/stance, target, range, recast and charges. Catalog entries reference `entry_contracts` for these shared conditions. Availability for the current weapon does not establish or erase learning. These four jobs grant no pet-command catalog. No player spellbook, inventory, merits, jobs, or progression is changed by a Trust profile.

Stats keep the existing native formulas and multipliers with a separate cached stat level: the regular summon-level snapshot below 99, otherwise 99 plus the native weighted item-level difference, capped at 119. Support contributes at half the stat level; its action level remains 99. The native skill table still caps at 99. Existing earned native progression and modifiers are preserved; no passive player gift-stat or ML package is added. This does not claim an exact Square Enix formula or raw player-stat parity.

The ordinary 17-Trust alliance extension is separate and defaults off. It retains exact authorized Twills admission and ordinary idle-mode guards. QA and retail-control evidence lanes remain distinct. That extension does not activate Valaineral's job profile or any unapproved variant; the per-Trust job setting also defaults off.

Ordinary 17-Trust gameplay uses one server combat roster: Twills and all seventeen owned Trusts. Party selectors and party support consider that shared roster. The three groups of six are client packet/display projections and do not divide combat support into three parties. Native action target/context checks remain in use, and recipients in qualified ordinary or developed-Trust lanes obey the native AoE radius. This shared group/support scope is a Mochirii extension; exact retail subparty eligibility is not claimed.

The Valaineral JSON now records the candidate source audit of all 20 PLD/WAR JP consumers and selected merit formulas. Intervene applies actual physical HP damage; Invincible adds static CE; Sentinel and actual divine casts compose qualified special enmity; Holy Circle fills missing damage consumers using source-type 6 cast provenance. Existing spell/BLU/breath consumers receive no duplicate term. These are source candidates with unrun native fixtures. Restraint retains the native accumulation factor 1.4, which does not establish 40% less time to cap. Double Attack JP is currently qualified in source only for native DOUBLE swings; WS multi-attack scope is unverified. Holy Circle preserves recipient-based JP initialization, so the accepted model gives Valaineral 35 resistance and an ordinary recipient without PLD JP 15; caster-wide JP propagation and exact retail units/rounding remain unresolved. Hybrid magic inherits its adjusted physical component once. None of this claims retail numerical parity.

Optional ordinary verification uses the existing native map logger, with bounded record shapes and an independent conservative 64 MiB charged budget. Capture requires `logging.LOG_INFO`, `main.ENABLE_TRUST_ACTION_LOG`, `main.TRUST_ACTION_LOG_PACKET_RESULTS`, `main.TRUST_ACTION_LOG_MAP_ECHO`, the matching `main.TRUST_ACTION_LOG_PLAYER`, and valid ordinary Twills entitlement/state admission. Truncation disables only this trace. Native Raise-finish records supplement HP/MP and animation with Weakness/Reraise fields; the record's presence alone is not revival acceptance. No additional file writer or QA session is created.
